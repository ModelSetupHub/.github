# ModelSetupHub

**مدل‌های AI محلی را نصب، تنظیم و اندازه‌گیری کنید — با هر سطح مهارتی که دارید.**

[English](README.md) · فارسی

اجرای مدل‌های AI روی کامپیوتر شخصی امروز ممکن است، ولی راه‌اندازی‌اش دردناک است. کاربر باید بداند کارت گرافیکش چقدر
VRAM دارد، کدام مدل در آن جا می‌شود، چه پارامترهایی را برای سرعت بهتر عوض کند، و وقتی چیزی کار نکرد خطای مبهم
`llama-server` چه معنایی دارد. بیشتر این‌ها حدس‌هایی است پخش‌شده در پست‌های انجمن.

ModelSetupHub یک جعبه‌ابزار متن‌باز است که همین فرایند را کنترل‌شده و قابل اندازه‌گیری می‌کند: سخت‌افزار را می‌شناسد،
سرویس Ollama را مدیریت می‌کند، مدل‌ها را نصب و اجرا می‌کند، و — بخشی که بیشتر ابزارها از آن می‌گذرند — همان پرامپت‌ها را
با چند مجموعه پارامتر مختلف اجرا می‌کند تا ببینید کدام کانفیگ روی دستگاه شما واقعاً سریع‌تر است. مدل‌های پایتونی مسیر
مستقل خودشان را دارند: یک checkpoint از YOLO بگیرید، یک محیط آماده کنید، و از دل یک اسکریپت اجرایش کنید.

## سه راه ورود، یک موتور

همه‌ی کار واقعی در **Core** انجام می‌شود. دو ریپوی دیگر راه‌های متفاوت رسیدن به آن هستند، برای آدم‌های متفاوت، و روی یک
دستگاه قابل جایگزینی با یکدیگرند.

| ریپو | چیست | برای چه کسی |
| --- | --- | --- |
| [**Core**](https://github.com/ModelSetupHub/Core) | کتابخانه‌ی پایتونی که کار را انجام می‌دهد | اسکریپت‌نویسی خودتان |
| [**WebApp**](https://github.com/ModelSetupHub/WebApp) | داشبورد وب محلی روی همان توابع | کنترل کامل دستی |
| [**MCPServer**](https://github.com/ModelSetupHub/MCPServer) | سرور MCP که همان ابزارها را به یک AI agent می‌دهد | توصیف هدف به زبان معمولی |
| [**website**](https://github.com/ModelSetupHub/website) | سایت استاتیک معرفی محصول | هر کسی که می‌خواهد تصمیم بگیرد |

### Core — کتابخانه

پکیج پایتونی که بقیه فقط پوسته‌ی آن هستند، در پنج حوزه:

- **شناسایی سخت‌افزار** — جزئیات پردازنده، ماژول‌های حافظه، کارت‌های گرافیک NVIDIA همراه با VRAM و نسخه‌ی CUDA، و هر
  درایو با فضای آزادش.
- **Ollama** — چرخه‌ی عمر سرویس، از جمله نصب خودِ Ollama؛ چرخه‌ی عمر مدل‌های محلی (ثبت، اجرا، پیش‌بارگذاری، تخلیه،
  کانفیگ، حذف)؛ و بنچمارک پارامترها با گزارش توان عبور توکن.
- **محیط‌های پایتون** — چرخه‌ی عمر محیط مجازی، پکیج‌ها با pip، اجرای اسکریپت، و پیدا کردن نسخه‌های پایتونی که از قبل نصب
  شده‌اند. همین مسیر است که مدل‌های پایتونی مثل YOLO از آن استفاده می‌کنند.
- **دانلود** — صفی که فایل‌های حجیم را یکی‌یکی می‌گیرد، با نگه داشتن موقت، ادامه دادن، تلاش مجدد، سرعت انتقال و لغو، و
  محدود به فهرست ثابتی از میزبان‌های مورد اعتماد.
- **لاگ** — یک لاگ اجرای ساختاریافته که هر عملیات در آن می‌نویسد و بعداً قابل خواندن و فیلتر کردن است.

این فقط یک کتابخانه است و نه چیز دیگر: نه ابزار خط فرمانی، نه سروری، نه رابطی. آن را import می‌کنید و توابعش را صدا
می‌زنید.

### WebApp — داشبورد وب

یک داشبورد محلی برای کسی که می‌داند چه می‌خواهد. هیچ تصمیمی جای شما گرفته نمی‌شود؛ این کار را سریع‌تر و دقیق‌تر می‌کند،
اما فرض می‌گیرد می‌دانید context window چیست. به دو زبان انگلیسی و فارسی، با چیدمان کامل راست‌به‌چپ. بخش‌هایی از
جعبه‌ابزار را پوشش می‌دهد که با یک رابط گرافیکی می‌خوانند — ابزارهای محیط پایتون و دانلود‌منیجر جزو آن‌ها نیستند. چهار تب:

- **System** — اسکن کامل سخت‌افزار؛ از اینجا شروع کنید، چون عدد VRAM تعیین می‌کند چه مدلی قابل بارگذاری است.
- **Ollama** — وضعیت نصب، کنترل پروسه‌ی سرور محلی، و نصب خودِ Ollama.
- **Models** — فهرست مدل‌های نصب‌شده و بارگذاری‌شده با اطلاعات، بارگذاری، توقف و حذف روی هر سطر، به‌علاوه فرم‌هایی برای
  اجرای پرامپت، ثبت یک فایل GGUF محلی، و ساختن نسخه‌ی کانفیگ‌شده از یک مدل.
- **Benchmark** — قابلیت شاخص. یک مدل و چند پرامپت انتخاب می‌کنید، چند مجموعه پارامتر دستی از میان ۲۳ گزینه‌ی تولید یا
  با ورود یک فایل JSON تعریف می‌کنید، و همه را اجرا می‌کنید. نتیجه با حکم شروع می‌شود: کدام کانفیگ سریع‌تر تولید کرد و با
  چه اختلافی از نفر دوم.

### MCPServer — رابط عامل

یک سرور MCP که جعبه‌ابزار را در اختیار یک AI agent می‌گذارد، تا بتوانید بگویید *یک مدل کدنویسی مناسب سیستم من نصب کن* و
agent خودش مراحل را انتخاب کند. ۵۹ ابزار در حوزه‌های سیستم، سرویس، مدل‌ها، بنچمارک، محیط‌های پایتون، دانلود و لاگ ارائه
می‌دهد.

عملیات‌های طولانی خودشان را در گفتگو گزارش می‌دهند: دانلود و بنچمارک یک نوار پیشرفت زنده کنار پیام دستیار رسم می‌کنند، با
دکمه‌ی **Cancel** که عملیات را تمام می‌کند *و* آنچه ساخته را برمی‌گرداند، و **Stop** برای دانلودها که انتقال را معلق
می‌کند و بعداً از همان‌جا که مانده ادامه می‌دهد. بعضی ابزارها عمداً ارائه نشده‌اند — مثلاً نوشتن در لاگ اجرا، تا کلاینت
نتواند رکورد جعلی در تاریخ اجرا تزریق کند.

### website — سایت معرفی

یک سایت استاتیک که پروژه را به انگلیسی و فارسی معرفی می‌کند.

## از کدام شروع کنم؟

- رابط گرافیکی می‌خواهید و می‌دانید چه می‌کنید ← **WebApp**.
- ترجیح می‌دهید هدف را توصیف کنید و agent کار را ببرد ← **MCPServer**.
- خودتان automation می‌نویسید ← **Core** به‌تنهایی.

`Core` یک git submodule در هر دو رابط است، پس هر کدام باید قبل از اجرا آن را بگیرد.

<div dir="ltr">

```bash
# the dashboard
git clone --recurse-submodules https://github.com/ModelSetupHub/WebApp.git
cd WebApp
python -m venv .venv && .venv\Scripts\activate
pip install -e ./core
pip install -r requirements.txt
python app.py            # then open http://127.0.0.1:5000/
```

```bash
# the MCP server
git clone --recurse-submodules https://github.com/ModelSetupHub/MCPServer.git
cd MCPServer
python utils/install_mshcore.py
pip install -r requirements.txt
python main.py           # then register it in your client under mcpServers
```

</div>

نصب کردن submodule به‌صورت پکیج همان مرحله‌ای است که راحت از قلم می‌افتد. بدون آن هر فراخوانی با
`ModuleNotFoundError: No module named 'MSHCore'` شکست می‌خورد، چون هر دو رابط آن را با نام پکیج import می‌کنند نه با مسیر
فایل.

## پیش‌نیازها

- پایتون ۳.۱۰ یا جدیدتر
- Git، برای گرفتن submodule هسته

هر ریپو وابستگی‌هایش را در `requirements.txt` پین می‌کند، و `Core` آن‌ها را در `pyproject.toml` هم اعلام کرده، پس نصب کردنش
خودش وابستگی‌ها را می‌آورد.

## چیزهایی که بهتر است پیش از نصب بدانید

اینجا شفافیت از براقی مفیدتر است، پس این‌ها صریح گفته می‌شوند نه پنهان:

- **فعلاً فقط ویندوز.** شناسایی سخت‌افزار روی PowerShell و WMI و شناسایی GPU روی `nvidia-smi` ساخته شده، پس آن بخش جای
  دیگر کم‌جزئیات‌تر است و کارت‌های گرافیک AMD یا Intel هنوز گزارش نمی‌شوند.
- **داشبورد احراز هویت ندارد.** یک سرور محلی است که اندپوینت‌هایش Ollama را روشن می‌کنند، مدل بار می‌کنند و حذف می‌کنند،
  و نصب‌کننده روی میزبان اجرا می‌کنند. روی localhost نگهش دارید؛ برای نشستن روی یک اینترفیس شبکه یا پشت reverse proxy
  عمومی ساخته نشده.
- **داشبورد زیرمجموعه‌ای از جعبه‌ابزار را پوشش می‌دهد.** ابزارهای محیط پایتون و دانلود‌منیجر از طریق Core و سرور MCP در
  دسترس‌اند، نه از داشبورد.
- **حذف مدل بازگشت‌پذیر نیست**، در هیچ‌کدام از دو رابط، و لغو کردن یک دانلود فایل‌هایی را که آن دانلود تولید کرده حذف
  می‌کند.

## وضعیت و مجوز

نوپا اما کارآمد، و در حال توسعه‌ی فعال. هر چهار ریپو عمومی، رایگان و متن‌باز هستند. issue و pull request در ریپویی که
تغییر به آن مربوط است پذیرفته می‌شود — تغییرات رفتاری معمولاً به **Core** مربوط‌اند، چون رابط‌ها فقط آن را صدا می‌زنند.
